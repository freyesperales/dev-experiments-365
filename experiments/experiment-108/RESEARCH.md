## What the research changed

- The first idea was "find the malicious script in your page". Sources 14 to 17 show that the largest Shopify incident of the year could not be found that way: the file was clean and the code arrived as data. The tool is therefore an inventory of who can run code, with honest limits, and not a malware scanner.
- Source 20 gave the two most useful rules: the exact comment Shopify prints around app blocks, and a real case of an imitation domain sitting next to a legitimate app block that the owner could not tell apart.
- Sources 3 and 8 look contradictory (script tags are removed on uninstall; some theme code is not). The tool keeps them apart: a legacy script tag "should belong to an app that is still installed", while a script written in the theme "stays when you uninstall apps".
- Sources 23 and 24 show merchants editing `content_for_header` to hide a script, which source 4 says not to do. That became the `theme.liquid` warning.

## Not verified in this run (used only as best-effort heuristics, and said so in the README)

- The theme asset paths (`/cdn/shop/t/<n>/assets/`, `/s/files/.../t/<n>/assets/`), the `Shopify.theme` object, the pixel configuration list and the list of Shopify-owned domains come from how storefront pages look, not from a documentation page. No real store was fetched to confirm them.
- The "BEGIN app snippet" variant of the app block comment is accepted but was not seen in a source.
- The list of well-known services was not checked against each provider's documentation.
