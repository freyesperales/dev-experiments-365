# Weekly report — 2026-W48 (23 to 27 November 2026)

This week's tools were run, read-only, against three websites run by the lab's owner. They are named Site 1, Site 2 and Site 3 (the same sites, in the same order, as in [2026-W47](2026-W47.md)); domains are not published here.

**Method.** Passive only: DNS lookups through public resolvers, one GET of each home page (response headers and public HTML), one GET of `/.well-known/security.txt`, and one TLS handshake to read the certificate the server presents. At most 3 HTTP(S) connections per site. No path guessing, no login pages, no enumeration. Date of the checks: 2026-11-27. Certificate Transparency (crt.sh) returned HTTP 502 during the run, so certificate dates come from the handshake instead.

## Findings and generic fixes

### Site 1
- **High — the Content Security Policy allows `'unsafe-inline'` and `'unsafe-eval'` in scripts.** Unchanged since W47. Aduana counts 41 inline `<script>` blocks on the home page and prints a stricter report-only policy with one hash per block. Fix: deploy that policy as `Content-Security-Policy-Report-Only` for a week, then move the blocks to files or keep the hashes, and remove `'unsafe-eval'`.
- **Low — DMARC has no `rua` address,** so there are no aggregate reports to read with Recuento and no way to see who sends mail as the domain. Fix: add `rua=mailto:` with a mailbox.
- **Low — no CAA record, no `security.txt`, no MTA-STS, DMARC at `p=quarantine`.** Unchanged; fixes as in W47.

### Site 2
- **Good — the certificate was renewed** (W47 flagged 10 days left; now 68).
- **High — the CSP allows `'unsafe-inline'` in scripts.** Unchanged.
- **Check — the page also sets a CSP in a `<meta>` tag.** In a `<meta>` policy, `frame-ancestors`, `report-uri`, `report-to` and `sandbox` are ignored and Report-Only cannot be used. Two policies are combined, so the stricter one wins on each request. Fix: keep a single policy in the HTTP header.
- **Check — the CSP does not list every origin the Google tag needs** according to Google's own CSP guide (for example `https://*.google.com` in `connect-src`). Some measurements can be blocked silently. Fix: compare with Aduana's starter policy in report-only mode.
- **Medium — DMARC has `sp=none` while the main policy is `quarantine`.** Unchanged. Fix: remove `sp=`.
- **Info — `pct`, `rf` and `ri` in DMARC are obsolete (RFC 9989).** Unchanged.

### Site 3
- **Good — the certificate was renewed** (W47: 29 days left; now 57).
- **High — the CSP allows `'unsafe-inline'`, and `'unsafe-eval'` (medium).** Unchanged. 71 inline scripts on the home page make the hash route long; nonces from the server are the practical fix.
- **Medium — DMARC `sp=none`.** Unchanged.
- **Low — `X-XSS-Protection: 1; mode=block`; Info — `Expect-CT`, and `pct`/`rf`/`ri` in DMARC are obsolete.** Unchanged.
- **Low — no CAA record, no `security.txt`, no MTA-STS.** Unchanged.

### All three
- DNSSEC is off (optional).
- None of the three has changed a header or a DNS record since W47; the two certificate renewals were automatic.

## Not applicable to a live site

- **Recuento (107)** reads the DMARC aggregate reports that arrive by email. To use it on Sites 2 and 3: download the `.xml.gz` or `.zip` attachments from the `rua` mailbox and drop them on the demo. Site 1 first needs an `rua` address.
- **Llavero (110)** reads the permissions an app asks for when you connect it to Google or Microsoft 365. To use it: paste the consent screen text, or the scope field of an n8n, Make or Zapier credential, before clicking "Allow".
- **Equipaje (111)** needs the list of files in the public folder, which is not visible from outside and must not be guessed. To use it on these sites: copy the file list of `public_html` from the hosting file manager (or `ls -la`), choose "my website public folder", and paste `.htaccess` too. On the code side: `node equipaje.js --dir .` in each project folder before the next deploy.
