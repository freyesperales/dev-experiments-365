# Weekly report — 2026-W47 (16 to 20 November 2026)

This week's tools were run, read-only, against three websites run by the lab's owner. They are named Site 1, Site 2 and Site 3; domains are not published here.

**Method.** Passive only: DNS lookups through public resolvers, one GET of each home page (response headers and public HTML), one or two GETs of `/.well-known/security.txt`, and Certificate Transparency logs. At most 4 HTTP requests per site. No path guessing, no login pages, no enumeration. Date of the checks: 2026-11-20.

## Findings and generic fixes

### Site 1
- **High — the Content Security Policy allows `'unsafe-inline'` and `'unsafe-eval'` in scripts.** With both, the policy stops very little injected code. Fix: move inline scripts to files or use nonces, remove `'unsafe-eval'`, and test first with `Content-Security-Policy-Report-Only`.
- **Low — DMARC has no `rua` address.** Nobody receives the reports that show who is sending mail as the domain. Fix: add `rua=mailto:` with a mailbox or a free report service.
- **Low — DMARC is `p=quarantine`.** Fix: move to `p=reject` once the reports have been clean for some weeks.
- **Low — no CAA record.** Any public certificate authority can issue for the domain. Fix: add CAA records for the authorities actually in use.
- **Low — no `security.txt`.** Someone who finds a problem has no clear way to report it. Fix: publish `/.well-known/security.txt` with a contact and an expiry date (RFC 9116).
- **Low — no MTA-STS.** Fix: publish a policy in `testing` mode first.
- **Review — 7 blocks of text in the home page are hidden with the `hidden` attribute.** They are ordinary page sections, with no instructions aimed at an AI. Worth knowing because AI assistants read them while visitors may not see them.
- Certificate: 40 days left, normal for a 90-day certificate.

### Site 2
- **Check now — the newest certificate in Certificate Transparency expires in 10 days.** A 90-day certificate is normally renewed with about 30 days left, so a renewal should already be visible. Fix: check the renewal status at the hosting or CDN panel and force a renewal if it is stuck. This is a reading of public logs, not of the certificate the server presents; logs can lag.
- **High — the Content Security Policy allows `'unsafe-inline'` in scripts.** Fix as for Site 1.
- **Medium — DMARC has `sp=none` while the main policy is `quarantine`.** Any subdomain can be spoofed. Fix: remove `sp=` so subdomains inherit the main policy.
- **Low — DMARC is `p=quarantine`; no MTA-STS; no CAA record.** Fixes as for Site 1.
- **Info — the DMARC record still has `pct`, `rf` and `ri`.** They were removed from the standard (RFC 9989) and are ignored. Fix: delete them.
- Good: `security.txt` is present and valid until mid 2027; HSTS with preload; no hidden text in the home page.

### Site 3
- **High — the Content Security Policy allows `'unsafe-inline'`, and `'unsafe-eval'` (medium).** Fix as for Site 1.
- **Medium — DMARC has `sp=none` while the main policy is `quarantine`.** Fix as for Site 2.
- **Low — `X-XSS-Protection: 1; mode=block`.** The header is obsolete and that value can create problems in old browsers. Fix: set it to `0` or remove it.
- **Low — no CAA record; no `security.txt`; no MTA-STS; DMARC is `p=quarantine`.** Fixes as above.
- **Info — `Expect-CT` is obsolete** and browsers ignore it; the DMARC record has the obsolete `pct`, `rf` and `ri` tags. Fix: remove them.
- **Watch — the certificate has 29 days left.** That is the point where automatic renewal normally starts. Fix: look again in a week.
- **Review — 2 blocks of hidden text in the home page** (a product list and a blog teaser). No instructions aimed at an AI.

### All three
- DNSSEC is off. It is optional; turn it on if the DNS provider offers it with one click.
- No key in a known format appears in the public HTML of the home pages.

## Not applicable to a live site

- **Vigía (101)** needs the plugin list, which is not public and must not be guessed from outside. To use it: in WordPress go to Tools → Site Health → Info → "Copy site info to clipboard", or run `wp plugin list`, and paste the result into the demo.
- **Derrame (104)** is meant for files that should never be public. To use it on your own repositories: `node derrame.js .env`, or `git log -p -- .env | node derrame.js -` to see whether a key was ever committed. Checking whether `/.env` or `/.git` is reachable on a live site would mean guessing paths, which this report does not do.
